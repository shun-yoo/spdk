# SPDK 개요

기준 소스: SPDK master `ae5c062` (27.01-pre, 2026-10-12). 줄 번호는 바뀔 수 있으니 함수 이름으로 찾는다.

## SPDK가 뭔가

SPDK(Storage Performance Development Kit)는 **사용자 프로그램이 커널 없이 SSD를 직접 제어하게 해 주는 것이 핵심이고, 그 위에 여러 부품을 얹어 쓰는 도구 모음**이다.

보통은 프로그램이 커널에 읽기를 부탁하고, 커널 드라이버가 SSD에 명령을 내리고, 끝나면 커널이 프로그램을 깨운다. 요청마다 커널을 거치니까 요청이 아주 많으면 그 비용이 커진다.

SPDK는 이렇게 한다.

- SSD를 커널 nvme 드라이버에서 떼어 내 `vfio-pci`(리눅스 커널에 있는, PCIe 장치를 사용자 프로그램에 넘겨주는 드라이버)에 붙인다. 그러면 SPDK가 SSD 큐에 명령을 직접 쓸 수 있다.
- 완료는 인터럽트를 기다리지 않고 polling으로 확인한다. 빠른 대신 그 일을 하는 CPU 코어가 계속 돈다.
- 큐 하나를 스레드 하나가 소유해서, 요청 경로에 락이 없다.

## 구성

SPDK는 뼈대 기능 위에 부품을 얹는 구조다. 이 노트에서 다루는 것은 아래 세 덩어리다.

| 덩어리 | 하는 일 | 위치 |
|---|---|---|
| 직접 제어 (NVMe 드라이버) | SSD에 NVMe 명령을 직접 보내고 완료를 확인 | `lib/nvme/` (로컬 SSD는 `nvme_pcie.c`) |
| 블록 장치 계층 (bdev) | "디스크"를 추상화한 층. "몇 번 블록 읽기"를 아래에 붙은 장치에 넘긴다 | `lib/bdev/`, `module/bdev/` (`nvme`, `raid`, `malloc` 등) |
| 네트워크 (NVMe-oF) | 네트워크 너머 SSD와 NVMe 명령을 주고받는다. 타겟과 이니시에이터가 있다 | 타겟 `lib/nvmf/`, 이니시에이터 `lib/nvme/` (`nvme_rdma.c`, `nvme_tcp.c`) |

이 밖에 가속 모듈(`module/accel/`: 복사·암호화 같은 계산을 하드웨어에 맡김), 이벤트·스레드 프레임워크 등이 있다.

bdev 아래에는 이런 것을 붙일 수 있다.

- 실제 SSD (`module/bdev/nvme/`): 직접 제어 코드를 쓴다.
- 여러 SSD를 묶은 RAID (`module/bdev/raid/`)
- 메모리로 만든 가짜 디스크 (`module/bdev/malloc/`): 테스트·성능 측정용

그래서 SPDK로 만든 프로그램이라도 어떤 부품을 붙이느냐에 따라 직접 제어를 안 쓸 수도 있다. 예를 들어 NVMe-oF 타겟 뒤에 `malloc`을 붙이면 네트워크 부분과 bdev만 쓰인다.

## 직접 제어와 네트워크의 관계

직접 제어가 바닥에 있고, NVMe-oF가 그 위에 올라간다.

- **타겟**은 네트워크로 받은 요청을 bdev를 거쳐 직접 제어 코드로 SSD에서 처리한다. 직접 제어 코드는 로컬 프로그램이 쓸 때와 같은 코드다.
- **이니시에이터**는 로컬 SSD를 쓸 때와 같은 읽기 함수(`spdk_nvme_ns_cmd_read`)를 쓴다. 그 아래 연결 방식만 다르다. 로컬이면 PCIe로 SSD에 직접 보내고, 리모트면 RDMA나 TCP로 타겟에 보낸다.

네트워크 부분은 [nvme-of.md](nvme-of.md)에 정리했다.
